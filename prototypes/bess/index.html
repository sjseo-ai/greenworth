왜 P-IRR 대신 E-IRR인가
대출금리가 원리금 상환액을 통해 직접 반영되는 지표라 E-IRR을 씁니다. 본 모델의 P-IRR은 이자비용의 법인세 절감효과만 반영하고 원리금 상환 자체는 프로젝트 현금흐름에서 빠지는 정의라, 금리가 오히려 P-IRR을 올리는 역설이 있어 대출금리 민감도 표에는 부적합합니다.

시나리오 비교표

열 = 시나리오, 행 = 항목. 결과 행의 초록은 가장 유리한 값, 빨강은 가장 불리한 값입니다(적정 입찰단가는 같은 목표를 더 낮은 단가로 달성할수록 유리 · 시나리오가 2개 이상일 때만 표시).
다운로드 안내 — JSON · CSV · 서식 적용 엑셀(.xlsx)

"현재값 저장"을 누르면 이 브라우저(localStorage)에 저장됨과 동시에, 그 시나리오의 입력 모델 전체를 담은 .json 파일이 즉시 다운로드됩니다 — 다른 기기·다른 사람과 공유하거나 나중에 정확히 그 시점 값으로 되돌아가고 싶을 때 이 파일을 보관하세요. 저장된 시나리오 목록의 "다운로드" 버튼으로 언제든 같은 파일을 다시 받을 수 있습니다.

"CSV 다운로드"는 지금까지 저장한 모든 시나리오를 한 파일로 나란히 비교하기 위한 별도 기능입니다 — .csv(엑셀에서 그대로 열림)이며, 1) Assumption(입력값, 계산된 표시값 포함) · 2) Summary(핵심 결과지표) · 3) Appendix(연도별 현금흐름 상세 — DSCR 게이트·이익준비금 잔여액까지 반영해 저장 시점 값으로 다시 계산) 세 절이 순서대로 들어 있습니다.

서식이 적용된 다중 시트 엑셀(.xlsx)이 필요하면 — 이 뷰어는 .xlsx 저장을 허용하지 않으므로, 위에서 받은 시나리오 .json 파일을 프로젝트 폴더의 ESS_엑셀변환.bat에 끌어다 놓으세요(여러 개를 함께 놓으면 '시나리오 비교' 시트가 추가됩니다). 요약 · 입력값 · 연도별 현금흐름 · 민감도 · 가격환산 · KCH 개발수수료 · 부록 3장(손익계산서·부채상환·현금흐름 전체)으로 된 .xlsx가 첫 json과 같은 폴더에 ESS_적정입찰단가_모델_사업명_날짜.xlsx로 만들어지고 바로 Excel로 열립니다. 숫자는 숫자로(비율은 % 서식) 들어가 정렬·차트·수식을 그대로 쓸 수 있고, 수치는 이 화면과 같은 계산 엔진으로 다시 계산합니다.

KCH 개발수수료 — 생애주기 누적 총 수취액

ESS 프로젝트 자체의 발전매출과는 별개로, KCH가 개발자(Developer)로서 SPC로부터 받는 4개 수수료(① 부지 임대료 ② 사전개발비 ③ 공동접속료 ④ 운영수익)를 억원 단위 총액으로 입력받아 생애주기 누적 총 수취액을 계산합니다.

산정 방식 설명
기본은 "총액 직접 입력" 모드 — 4개 금액을 원하는 값 그대로 입력하면 운영기간·연간 상승률을 반영한 생애주기 누적 총 수취액이 계산되고, ① 버튼 한 번으로 이 총액을 A. 산정 기준의 "목표 당사 이익"에 반영해 적정 입찰단가를 다시 계산하거나, ② "가격환산" 탭의 입찰가격에 이 총액을 이 프로젝트의 생애주기 총 발전량 기준 원/kWh로 자동 환산해 실시간으로 더해서 반영합니다(②는 버튼 없이 즉시 갱신 — 단가산정 자체의 P-IRR·NPV·당사이익에는 영향 없음). 예전 방식("목표 IRR 역산" — 기준총액에 공통 가격배율을 곱해 목표 IRR을 만족하는 배율을 이분탐색으로 찾는 ESS_단가산정모델.xlsx 로직)은 레거시 옵션으로 남겨두었습니다. 설비용량·저장용량은 C. 발전매출의 계약용량에 연동되고, 사업기간은 ESS 입찰단가 계산부와 별도로 여기서 입력합니다.

확정 필요 항목

결과 수치에 영향을 주지만 아직 확정되지 않은 가정입니다. KCH 내부 기준이나 원문 대조로 확정되기 전까지 이 화면의 모든 결과는 사전검토용 지시값입니다.

  • KCH 개발수수료 단가산정 — 할인율(7.5%)·4개 수수료 기준총액(억원)은 ESS_단가산정모델.xlsx의 초안 예시값(원/kW 단가 × 예시 설비용량 50MW)을 억원 총액으로 환산해 그대로 옮긴 것 — 실제 KCH 내부 기준으로 교체 필요. 4개 수익원은 원/kW 단가가 아니라 "현재 설비용량 기준" 총액(억원)으로 입력받으며, 민감도표에서 다른 설비용량을 비교할 때만 총액을 비례로 스케일링함. 이 탭의 설비용량·저장용량은 C. 발전매출의 계약용량에 연동됨(저장용량 = 계약용량 × 6h — 용량은 거의 바뀌지 않아 한 곳에서만 입력). 사업기간(1. 사업 기본정보)은 여전히 별도 입력이라 같은 프로젝트면 맞춰 입력해야 함 — 다만 수취액 총액 → 가격환산 입찰가격 원/kWh 환산 자동연결은 반영 완료(C. 발전매출의 계약용량·가동률·운영기간 기준으로 환산)
  • KCH 개발수수료 "총액 직접 입력" 모드 — ① 부지 임대료·④ 운영수익은 "억원/년"(연간, 상승률 적용) 필드이고 ② 사전개발비·③ 공동접속료(기본 "연간" 방식, "일시금"으로 바꾸면 COD 1회)는 "억원" 필드라, 4개 입력값을 단순히 더한 숫자가 아니라 "생애주기 누적 총 수취액"(연간 항목 × 운영기간, 상승률 반영)이 "목표 당사 이익"과 정합성 있게 연결되도록 계산함 — 예: 임대료 30억을 만들려면 상승률을 0%로 두고 연간 2억×15년으로 입력해야 함. "▶ 반영" 버튼은 클릭 시에만 동작하는 명시적 연결이며 자동 동기화는 하지 않음. 레거시 "목표 IRR 역산" 모드로 전환하면 민감도표의 "목표 IRR 이상" 강조 기준은 숨겨진 "목표 IRR" 입력값을 계속 참조함
  • 내부 재무모델 참고자료 기준으로 조정한 값 — DSCR 임계치(1.15/1.30배), 할인율(4.5%), 법인세 4단계 구간(3,000억 초과 26.4% 추가), 가동률 규칙(1년차 95%·2년차 96%·3년차~ 97%), 전력거래수수료(0.1193원/kWh), 당사(KCH) 지분율(20%) — 모두 실제 프로젝트 파이낸싱 조건을 참고한 값이므로, 본 사업에도 그대로 적용 가능한지 재확인 필요
  • 단가산정 — "당사 이익 목표" 기본값(100억원, 기준 지표=누적 순이익 세전)은 초안 설정값이며, 당사(KCH) 지분율(기본 20%)만큼만 배분된 금액을 목표로 함. 목표 금액·기준 지표·지분율이 실제 KCH 내부 기준과 맞는지 확인 필요
  • 반영하지 않은 구조적 차이 — 참고자료의 선순위차입금은 목표 DSCR 기반 부채 사이징(사이즈컬핑, 원금불균등 상환) 방식인데 본 프로토타입은 자기자본·주민채권을 비율(%) 또는 금액(억원)으로 넣고 선순위를 나머지로 두는 방식만 지원함. 선순위 금리는 고정·변동(CD 91일물 연동, 3/6개월 조정) 혼합을 연 단위로 근사 반영하나 트랜치별 별도 상환조건은 미반영, CD금리는 고시값 자동 연동이 아니라 직접 입력(기본 2.80%는 예시). 또 등록세·신주발행비 등 지분조달비용 세부 항목은 미반영 — 필요 시 다음 이터레이션에서 검토
  • C. 발전매출 — 준공지연 페널티 1단계 계약가격 감액식: 공고 25p 원문 표가 PDF 추출 과정에서 병합 셀이 뒤섞여, "거래기간 유지 + 계약가격 × (15년×365−지연일수)/(15년×365)"로 초안 해석함. 원문 표(엑셀/한글 원본) 대조 확인 필요
  • C. 발전매출 — 이행률 패널티: 원문은 일간·충방전별 급전지시량 대비 계량값으로 계산하나, 시간대별 지시 데이터가 없어 "연평균 미이행률(%)" 단일값으로 근사함. 실제 운영 데이터 확보 시 일단위 산식으로 정교화 필요
  • C. 발전매출 — 공급량 산정표(①~⑤)는 가동률만 반영했고, 운전효율 체인(TR·PCS·Cable 효율, DC RTE)과 잔존율(경년열화)은 아직 미반영 — 반영 필요 여부 확인
  • D·E. CAPEX·OPEX — 실제 장비 대수(배터리 150대·PCS 25대)로 기본값을 바꾸면서 배터리 유닛 대수·PCS 대수와 CAPEX·OPEX 배수 연동을 끊고 프로젝트 총액 직접 입력 방식으로 전환함(대수를 그대로 곱하면 총액이 비현실적으로 커지는 문제 해결)
  • D~F. CAPEX·OPEX·금융조건 — 실제 견적/계약 조건으로 교체 (현재는 사업성모델 앱 ESS 프리셋 초안값)
  • 목표 IRR — KCH 내부 허들레이트 확인

사업개요·발전매출·CAPEX·OPEX·금융세무 입력값으로 목표 당사 이익(또는 목표 IRR)을 만족하는 적정 입찰단가(원/kWh)를 역산하고, 그 값이 가격환산계산기의 입찰가격으로 자동 연결되어 가격평가점수까지 한 화면에서 확인합니다.

이 프로토타입은 이터레이션 1 범위(ESS 발전원 전용)로 배터리 증설(augmentation)은 단순화(미적용)했고, 이터레이션 2에서 KCH 개발수수료 단가산정 모델을 통합했습니다. 핵심 재무 로직(총투자비 반복수렴, 원리금균등상환, 누진세+이월결손금, DSCR 게이트 배당, 법정준비금)은 js/finance.js와 동일한 알고리즘으로 이식했습니다.
