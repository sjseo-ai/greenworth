서식이 적용된 다중 시트 엑셀(.xlsx)이 필요하면 — 이 뷰어는 .xlsx 저장을 허용하지 않으므로, 위에서 받은 시나리오 .json 파일을 프로젝트 폴더의 ESS_엑셀변환.bat에 끌어다 놓으세요. Assumptions·Summary·Funding·IS·Depreciation·DebtSchedule·CashFlow·KCH·가격환산 9개 시트로 된 .xlsx가 같은 폴더에 만들어지고 바로 Excel로 열립니다(수치는 이 화면과 동일하게 계산).

왜 P-IRR 대신 E-IRR인가
대출금리가 원리금 상환액을 통해 직접 반영되는 지표라 E-IRR을 씁니다. 본 모델의 P-IRR은 이자비용의 법인세 절감효과만 반영하고 원리금 상환 자체는 프로젝트 현금흐름에서 빠지는 정의라, 금리가 오히려 P-IRR을 올리는 역설이 있어 대출금리 민감도 표에는 부적합합니다.

아래 12개 항목은 결과 수치에 영향을 주지만 아직 KCH 내부 기준이나 원문 대조로 확정되지 않은 가정입니다.

  • KCH 개발수수료 단가산정 — 할인율(7.5%)·4개 수수료 기준총액(억원)은 ESS_단가산정모델.xlsx의 초안 예시값(원/kW 단가 × 예시 설비용량 50MW)을 억원 총액으로 환산해 그대로 옮긴 것 — 실제 KCH 내부 기준으로 교체 필요. 4개 수익원은 원/kW 단가가 아니라 "현재 설비용량 기준" 총액(억원)으로 입력받으며, 민감도표에서 다른 설비용량을 비교할 때만 총액을 비례로 스케일링함. 이 탭 자체의 설비용량·기간(1. 사업 기본정보)은 ESS 입찰단가 계산부와 별개의 독립 입력이라(KCH 자체 IRR 역산 계산에만 쓰임), 같은 프로젝트를 다룰 때는 양쪽에 값을 각각 맞춰 입력해야 함 — 다만 수취액 총액 → 가격환산 입찰가격 원/kWh 환산 자동연결은 반영 완료(C. 발전매출의 계약용량·가동률·운영기간 기준으로 환산)
  • KCH 개발수수료 "총액 직접 입력" 모드 — ① 부지 임대료·④ 운영수익은 "억원/년"(연간, 상승률 적용) 필드이고 ② 사전개발비·③ 공동접속료(기본 "연간" 방식, "일시금"으로 바꾸면 COD 1회)는 "억원" 필드라, 4개 입력값을 단순히 더한 숫자가 아니라 "생애주기 누적 총 수취액"(연간 항목 × 운영기간, 상승률 반영)이 "목표 당사 이익"과 정합성 있게 연결되도록 계산함 — 예: 임대료 30억을 만들려면 상승률을 0%로 두고 연간 2억×15년으로 입력해야 함. "▶ 반영" 버튼은 클릭 시에만 동작하는 명시적 연결이며 자동 동기화는 하지 않음. 레거시 "목표 IRR 역산" 모드로 전환하면 민감도표의 "목표 IRR 이상" 강조 기준은 숨겨진 "목표 IRR" 입력값을 계속 참조함
  • 내부 재무모델 참고자료 기준으로 조정한 값 — DSCR 임계치(1.15/1.30배), 할인율(4.5%), 법인세 4단계 구간(3,000억 초과 26.4% 추가), 가동률 규칙(1년차 95%·2년차 96%·3년차~ 97%), 전력거래수수료(0.1193원/kWh), 당사(KCH) 지분율(20%) — 모두 실제 프로젝트 파이낸싱 조건을 참고한 값이므로, 본 사업에도 그대로 적용 가능한지 재확인 필요
  • 단가산정 — "당사 이익 목표" 기본값(100억원, 기준 지표=누적 순이익 세전)은 초안 설정값이며, 당사(KCH) 지분율(기본 20%)만큼만 배분된 금액을 목표로 함. 목표 금액·기준 지표·지분율이 실제 KCH 내부 기준과 맞는지 확인 필요
  • 반영하지 않은 구조적 차이 — 참고자료의 선순위차입금은 목표 DSCR 기반 부채 사이징(사이즈컬핑, 원금불균등 상환) 방식인데 본 프로토타입은 고정 비율(자기자본/타인자본 %) 방식만 지원함. 또 등록세·신주발행비 등 지분조달비용 세부 항목, Tr.A(변동)/Tr.B(고정) 이원화 금리 구조는 미반영 — 필요 시 다음 이터레이션에서 검토
  • C. 발전매출 — 준공지연 페널티 1단계 계약가격 감액식: 공고 25p 원문 표가 PDF 추출 과정에서 병합 셀이 뒤섞여, "거래기간 유지 + 계약가격 × (15년×365−지연일수)/(15년×365)"로 초안 해석함. 원문 표(엑셀/한글 원본) 대조 확인 필요
  • C. 발전매출 — 이행률 패널티: 원문은 일간·충방전별 급전지시량 대비 계량값으로 계산하나, 시간대별 지시 데이터가 없어 "연평균 미이행률(%)" 단일값으로 근사함. 실제 운영 데이터 확보 시 일단위 산식으로 정교화 필요
  • C. 발전매출 — 공급량 산정표(①~⑤)는 가동률만 반영했고, 운전효율 체인(TR·PCS·Cable 효율, DC RTE)과 잔존율(경년열화)은 아직 미반영 — 반영 필요 여부 확인
  • D·E. CAPEX·OPEX — 실제 장비 대수(배터리 150대·PCS 25대)로 기본값을 바꾸면서 배터리 유닛 대수·PCS 대수와 CAPEX·OPEX 배수 연동을 끊고 프로젝트 총액 직접 입력 방식으로 전환함(대수를 그대로 곱하면 총액이 비현실적으로 커지는 문제 해결)
  • D~F. CAPEX·OPEX·금융조건 — 실제 견적/계약 조건으로 교체 (현재는 사업성모델 앱 ESS 프리셋 초안값)
  • 목표 IRR — KCH 내부 허들레이트 확인

사업개요·발전매출·CAPEX·OPEX·금융세무 입력값으로 목표 당사 이익(또는 목표 IRR)을 만족하는 적정 입찰단가(원/kWh)를 역산하고, 그 값이 가격환산계산기의 입찰가격으로 자동 연결되어 가격평가점수까지 한 화면에서 확인합니다.

이 프로토타입은 이터레이션 1 범위(ESS 발전원 전용)로 배터리 증설(augmentation)은 단순화(미적용)했고, 이터레이션 2에서 KCH 개발수수료 단가산정 모델을 통합했습니다. 핵심 재무 로직(총투자비 반복수렴, 원리금균등상환, 누진세+이월결손금, DSCR 게이트 배당, 법정준비금)은 js/finance.js와 동일한 알고리즘으로 이식했습니다.
