## 0. 이 문서의 목적

이 PRD는 위 기획문서들에 흩어져 있던 요구사항(핵심 변수 기반 재무모델 자동생성, 발전원별 입력, Sensitivity 분석, ESS 부속 도구 2종)을 하나의 **웹 프로토타입**으로 통합하기 위한 실행 사양이다. 처음부터 완성형을 만들지 않고, **3단계 이터레이션**으로 쪼개 각 단계마다 실제로 켜볼 수 있는 결과물이 나오게 한다. 각 이터레이션은 기획문서 "4. 성공 기준(3단계)"의 최소 성공/목표 성공/이상적 성공에 각각 대응한다.

## 1. 배경과 문제

- 현재는 프로젝트 검토마다 엑셀 재무모델을 수기로 만들고, 매크로 변수(금리·환율·물가상승률) 조합별로 반복 재계산해 Sensitivity 표를 손으로 작성한다. 프로젝트당 반나절~1일이 소요되고, 변수 조합이 늘수록 반복 계산 부담이 커진다.
- ESS 사업은 추가로 두 갈래 의사결정이 필요하다: ① KCH가 개발자로서 받을 4개 수수료(부지 임대료·사전개발비·공동접속료·운영수익) 단가를 목표 IRR에 맞춰 정하는 문제, ② ESS 중앙계약시장 입찰에서 입찰가격이 비가격점수 대비 얼마의 가치를 갖는지 환산하는 문제. 현재 이 둘은 각각 별도 엑셀 파일(Goal Seek 수동 실행)로만 존재한다.
- 세 가지 계산(재무모델·단가산정·가격환산)이 서로 다른 파일에 흩어져 있어, 가정을 하나 바꾸면 세 파일을 각각 다시 열어 손으로 맞춰야 한다.

## 2. 목표

| 구분 | 내용 |
| --- | --- |
| 제품 목표 | 핵심 변수만 입력하면 재무모델·투자지표·Sensitivity가 자동 계산되고, ESS의 경우 단가산정·가격환산까지 한 화면 흐름에서 이어지는 웹 프로토타입 |
| 성공 지표 | 프로젝트 1건당 사업성 분석 소요시간을 반나절~1일 → 1~2시간으로 단축 (기획문서 6장과 동일 기준) |

## 4. 범위 밖으로 명시적으로 제외하는 것 (기획문서 "Known model boundaries" 준용)

이 프로토타입은 참고용 사업성 검토 도구이며 감사된 투자자문이 아니다. 아래는 의도적 제외 항목이며, "구현이 빠졌다"는 이유로 임의로 추가하지 않는다.

- P50/P90 발전량 시나리오 선택, 월별/분기별 발전량·가격 곡선
- VAT, 자산별 세부 감가상각, 부채 스컬프팅(sculpting), 리파이낸싱
- 세율 프리셋은 역사적 예시이며 현행 세법을 반영하지 않음(세무자문 아님)
- 태양광: 일사량 시계열, 출력제한(커튼먼트), 인버터 교체 주기
- 육상풍력: 연 단위로 단순화한 검증 프리셋
- 해상풍력: 해저지반·항만·설치선 실측 견적, 월별 발전량 변동
- ESS: 충·방전 시계열, 주파수조정 등 보조서비스 정산, 배터리 효율의 연차별 완만한 하락

## 5. 핵심 사용자 시나리오

1. 사용자가 발전원(태양광/육상풍력/해상풍력/ESS)을 고르고 핵심 변수를 입력한다.
2. 시스템이 입력값을 검증(누락·이상값 체크, 업계 표준치 제안)하고 B/S·I/S·CF를 자동 생성한다.
3. IRR·NPV·배당 등 투자지표를 계산하고, 매크로 변수 조합별 Sensitivity를 보여준다.
4. 결과가 기준에 못 미치면 변수를 다시 조정한다(What-if 반복).
5. **(ESS만)** KCH 개발수수료 목표 IRR을 입력하면 4개 수수료 단가가 역산된다.
6. **(ESS만)** 입찰가격을 입력하면 가격평가점수와 비가격점수 1점의 가격 가치가 계산된다.
7. 담당자가 결과를 검토·승인하면 PDF 리포트로 정리되어 부서에 공유된다.

## 6. 기능 요구사항

### 6.1 발전원 선택 및 핵심 변수 입력 (공통)

- 발전원 4종(PV/ON/OF/ES) 중 1개 선택. 선택에 따라 입력 필드 세트가 바뀐다.
- 공통 입력 5섹션: 사업개요(설비용량·기간), 발전·매출(단가·이용률 또는 저장조건), CAPEX(7개 범주: 기자재/토목/전기/계통·선로/운송·설치/간접비/토지), OPEX, 금융·세무(WACC·세율·DSCR 등은 **읽기 전용 프리셋**으로 표시).
- 발전원별 차별 필드(다이어그램 기준):
  - PV: P75 이용률, 연간 성능저하율, REC 가중치
  - ON/OF: P75 이용률, REC 가중치, (OF만) 해상 특화 CAPEX 항목
  - ES: 저장시간, 연간 사이클, 왕복효율, 소내소비율, 배터리 증설 주기·단가, LTSA 단가 변경 시점·배율
- 필수 값 누락·범위 이상 시 인라인 경고 + 업계 표준치 제안값 노출.

### 6.2 재무모델 자동 생성 및 투자지표

- 입력값만으로 연도별 B/S·I/S·CF를 구성한다(추정재무제표).
- IRR(세전/세후, 프로젝트/지분), NPV, 배당(가능이익·법정준비금 반영), DSCR 게이트를 계산한다.
- B/S–I/S–CF 간 정합성(자기검증)을 계산 후 표시한다.

### 6.3 Sensitivity 분석

- 매크로 변수(금리·환율·물가상승률 등) 조합별로 재계산해 표/그래프로 보여준다.
- 최소 1개 축(예: 금리) 단일 민감도표는 이터레이션 1부터, 2축 조합(예: 가격×물가상승률) 매트릭스는 이터레이션 2부터.

### 6.4 ESS 단가산정 모델 (KCH 개발수수료)

- 입력: 설비 규모·기간, KCH 비용(용지비·개발비·관리비), 4개 수익원(부지 임대료/사전개발비/공동접속료/운영수익) 기준단가·상승률, 목표 IRR.
- **공통 가격배율** 하나로 4개 단가를 동시에 스케일링하고, 목표 IRR을 만족하는 배율을 자동으로 구한다(수치해석: 이분탐색 또는 뉴턴법 — 엑셀의 Goal Seek을 웹에서는 반복 계산 함수로 대체).
- 가격배율 × 설비용량 조합별 달성 IRR 민감도표(목표 IRR 이상 칸 강조).

### 6.5 ESS 가격환산 계산기

- 산식(전력거래소 공고 제2025-05호 Ⅲ.5 기준): `가격평가점수 = ROUND(최저입찰가격 ÷ 입찰가격 × 가격배점, 2)`
- 비가격점수 1점당 가격 환산: 방법 A(미분근사) `입찰가격² ÷ (최저가격 × 가격배점)`, 방법 B(±1점 정확값의 평균) — 이미 검증된 산식이므로 그대로 이식.
- 점수 변동(Δ점, −5~+5) 민감도표.
- **(이터레이션 2 이후)** 6.4의 목표 IRR 역산 판매단가를 입찰가격의 기본값으로 자동 연결.

### 6.6 결과 출력 및 협업

- 결과 웹페이지: 입력 요약 + 투자지표 + B/S·I/S·CF + Sensitivity 표.
- 변수 재입력 시 즉시 재계산되는 What-if 루프.
- PDF 리포트 자동 생성(투자지표 + 재무제표 + Sensitivity 요약), 필요 시 다운로드/공유.
- 여러 변수 시나리오(프로젝트)를 저장하고 나란히 비교.

## 9. 이터레이션 로드맵

### 이터레이션 1 — 최소 성공: 핵심 흐름 1회 작동

**목표**: "핵심 변수를 입력하면 재무모델과 투자지표가 한 번 자동 계산된다"를 증명한다. (기획문서 성공기준 "최소 성공"에 대응)

**범위**
- 발전원 1종만 지원 (ESS 우선 — 부속 도구 2개와 바로 이어지므로)
- 6.1의 공통 입력 5섹션 폼 (발전원별 차별 필드는 ESS 것만)
- 6.2 재무모델 자동 생성 + IRR/NPV/배당 계산
- 결과를 한 화면에 KPI + 간단한 표로 출력 (그래프·PDF 없음)
- Sensitivity·시나리오 저장·ESS 부속 도구는 이번 단계에 **포함하지 않음**

JSON을 읽어 우리 프로토타입과 대조한 핵심 발견:
- **ASSUMPTIONS 시트에 PCS계약용량/PCS설치용량/배터리계약용량/배터리설치용량이 명확히 분리되어 있어**, 직전에 반영한 "설치용량·계약용량 분리" 작업 방향이 실제 모델과 일치함을 재확인.

- 골든마스터 검증(엑셀 원본 값과 대조): 기본 입력값에서 공통 가격배율 0.2783배(엑셀 0.27828, 소수 첫 4자리 일치) · 달성 IRR 9.00%(엑셀 9.00183% — 엑셀 Goal Seek은 기본 허용오차 안에서 근사 수렴하는 반면 이분탐색 60회 반복은 사실상 완전 수렴이라, 산출 단가에 0.01% 내외 미세한 차이가 남는 것은 정상) · NPV 1.57억원(엑셀 1.57223 일치) · 총수익 38.31억원(엑셀 38.3107 일치) · KCH총비용 23.50억원(엑셀 23.5 완전 일치) · 민감도표 1.0배 행 값(17.0%/28.7%/39.8%/50.8%/61.7%/72.7%/83.8%)이 엑셀 원본과 소수 첫째 자리까지 정확히 일치함을 확인. 목표 IRR을 12%로 올리면 가격배율이 0.3214배로 상승, 500%처럼 비현실적인 목표를 주면 "가격배율 5.00배까지도 도달 못함" 오류 배너로 정상 실패 처리됨을 확인. 기존 ESS 입찰단가 계산부는 전역 이벤트 배선에서 `kch` 접두사 필드를 명시적으로 제외해 서로 간섭하지 않음(회귀 테스트로 기존 결과 40.79원/kWh 불변 확인). 콘솔 오류 없음.

**ESS 본체 Sensitivity 매트릭스 추가 (2026-08-31)**: 이터레이션 2 남은 두 항목(발전원 4종 확장 / ESS 본체 2축 Sensitivity) 중 어느 것부터 이어갈지 재확인한 결과, "발전원 4종 확장은 다른 인원이 진행 중이니 Sensitivity를 먼저 해달라"는 요청을 받아 진행 방향을 전환. 좌측 "단가산정모델"에서 계산된 현재 적정 입찰단가를 고정한 채, **선순위 대출금리 × OPEX 물가상승률**을 각각 현재 입력값 대비 −1.5%p~+1.5%p(0.5%p 간격, 7단)로 편차(Δ)를 주는 7×7 매트릭스를 추가:
- 처음에는 P-IRR(프로젝트 IRR)로 구현했는데, 테스트 중 "대출금리가 오를수록 오히려 P-IRR이 상승"하는 역설적인 결과를 발견. 원인 확인: 본 모델의 `projectFlowPreTax`는 EBITDA와 CAPEX만 반영하고 원리금 상환 자체는 차감하지 않으며, 법인세만 이자비용의 절세효과를 통해 간접 반영하는 구조라, 대출금리 상승 → 이자비용 증가 → 법인세 절감 → 세후 프로젝트 현금흐름 증가로 이어지는 것이었다(계산 자체는 정확했지만 "대출금리 민감도"라는 취지에는 반직관적이고 부적합한 지표). 지분 IRR(E-IRR, 배당세전)은 원리금 상환을 직접 차감하므로 대출금리에 직관적으로 반응해, 지표를 **E-IRR**로 교체하고 그 이유를 화면 설명문에 그대로 남겼다.
- 기준(Δ=0,0) 셀은 상단 결과 패널의 "달성 E-IRR(배당세전)" KPI와 정확히 일치하도록 구현(회귀 검증 완료)하고 시각적으로 테두리 강조, 기준 대비 E-IRR이 유지·개선되는 칸을 초록으로 강조.
- 헤드리스 브라우저로 검증: 기본값에서 중앙(0,0) 셀 7.45%가 "달성 E-IRR" KPI(7.45%)와 정확히 일치, 대출금리 −1.5%p 행은 8.32~9.22%로 전부 기준보다 높고 +1.5%p 행은 5.70~6.55%로 전부 기준보다 낮아 단조적으로 직관적인 방향성을 보임, OPEX 물가상승률도 같은 행 안에서 오른쪽으로 갈수록(상승률 증가) 단조 감소함을 확인. 선순위 대출금리 입력을 5.2%→6.5%로 바꾸면 매트릭스 기준값도 즉시 6.50%로 재중심화됨을 확인. 준공지연 3단계(계약 해지)처럼 상단 결과가 "N/A"인 상태에서는 매트릭스도 안내 문구로 정상적으로 비워짐을 확인. 콘솔 오류 없음.

**EPC 총액 수기입력 옵션 + 대출금리×EPC총액 Sensitivity (2026-08-31)**: 사용자가 "EPC 기자재별 단가를 13개나 입력하는 게 번거로우니 EPC 총액을 수기로 입력하는 것도 가능하게 하고, EPC 단가 Sensitivity도 대출금리 시나리오와 같은 방식으로 반영해달라"고 요청.

- **테스트 중 버그 발견 및 수정**: 모드 전환 시 총액 입력란에 `fmt()`(천단위 콤마 포맷터, 예: "1,005.0")를 그대로 대입했더니, 콤마가 포함된 문자열은 `type="number"` input에서 브라우저가 거부해 값이 통째로 빈 문자열로 리셋되는 문제가 발생 — CAPEX 총액이 0으로 읽혀 결과가 왜곡됐다(적정 입찰단가가 22.51원→10.64원으로 급락). `fmt()` 대신 순수 숫자 문자열(`itemizedSum.toFixed(1)`)로 교체해 수정. 이 참에 파일 전체에서 `.value = fmt(...)` 패턴을 모두 점검해, 다른 모든 자리는 `type="number"`가 없는(기본 텍스트) 비활성 표시 필드라 콤마가 있어도 문제없음을 확인 — 유사한 잠재 결함은 이 한 곳뿐이었음.
- 헤드리스 브라우저로 재검증: 항목별→총액 모드 전환 시 총액이 정확히 1005.0으로 채워지고 결과(22.51원)가 그대로 유지됨, 총액을 1500으로 직접 수정하면 결과가 28.35원으로 상승, 총액→항목별로 되돌리면 1,005.0억원·22.51원으로 정확히 복원됨을 확인. EPC 매트릭스는 기준(0,0) 셀이 "달성 E-IRR" KPI(7.45%)와 정확히 일치, EPC 총액이 늘어날수록·대출금리가 오를수록 E-IRR이 단조 감소하는 직관적인 방향성을 확인. 콘솔 오류 없음.

**KCH 개발수수료 단위 통일 — 원/kW 단가 폐지, 억원 총액으로 전환 (2026-08-31)**: 사용자가 "전체적으로 단위가 안 맞는 것 같다, 예를 들어 사전개발비가 150억 기준으로 보이는데 15,000원/kW로 표시되어 있다"고 지적하며, 총액 기준으로 억원 단위로 전체 통일해달라고 요청. 원인: `ESS_단가산정모델.xlsx`를 이식할 때 원본 그대로 "원/kW", "원/kW/년" 단가 × 설비용량(kW)으로 총액을 환산하는 구조를 그대로 옮겼는데, 이 단위가 다른 절(CAPEX·OPEX·KCH 비용 등은 전부 억원 총액)과 이질적이라 헷갈린다는 지적이었다.

- 부작용 처리: 기존 "가격배율×설비용량" 민감도표는 설비용량 열을 바꿔가며 원/kW 단가에 곱해 총액을 재계산하는 방식이었는데, 총액을 직접 입력하는 구조로 바뀌면서 설비용량을 바꿔도 더 이상 계산에 영향을 주지 않아 표가 무의미해지는 부작용이 있었다. 이를 "입력한 총액은 현재 설비용량 기준이며, 다른 설비용량을 가정할 때는 총액을 (가정 설비용량÷현재 설비용량) 비율로 비례 스케일링한다"는 보조 인자(`revenueCapacityScale`)로 해결해, 예전과 수학적으로 동일한 민감도표 결과를 유지.

- **공고 규정 위반(계산은 되지만 실무상 무효)**: 계약용량이 공고 Ⅰ.가·Ⅳ.가 기준 신고범위(10MW 초과~100MW 미만) 밖인데도 경고가 없던 것을 발견 → `contractCapacityRangeWarn` 추가(기존 `contractCapacityWarn`은 "설치용량 초과"만 검사하는 별도 항목이라 유지하고 신규 병설).
- **조용한 clamp로 사용자가 모를 수 있는 케이스**: ① 공사기간이 길거나 COD가 일러 착공연도가 사업 시작연도보다 앞서면 `developmentYears`가 `Math.max(0, ...)`로 조용히 0년으로 조정되는 것을 발견 → `developmentTimelineWarn` 추가. ② 연평균 미이행률이 0~100% 밖이면 `Math.min(100, Math.max(0, ...))`로 조용히 clamp되는 것을 발견 → `nonComplianceRangeWarn` 추가.
- **물리적으로 불가능한 값**: 운영연차별 가동률이 0~100% 밖(예: 150%)이면 발전량이 물리적 상한을 넘는데 경고가 없던 것을 발견 → `opRateRangeWarn` 추가. 당사(KCH) 지분율은 HTML `min="0" max="100"`가 있지만 JS단에서 강제되지 않아 150% 등도 그대로 입력·계산되던 것을 발견 → `kchShareRangeWarn` 추가.
- **입력 실수 방지**: CAPEX·OPEX 항목에 음수 값이 들어가도 합계에 그대로 반영되던 것을 발견 → `capexNegativeWarn`/`opexNegativeWarn` 추가(어떤 항목이 음수인지 라벨까지 명시).
- 헤드리스 브라우저로 11개 항목 각각 개별 트리거→경고 노출 확인→값 원복→경고 정상 해제까지 전수 검증(예: 자기자본70%+주민채권40%=110%→경고 노출 후 30%/5%로 복원 시 정상 해제, 원금거치10년=상환기간10년→경고, 계약용량 5MW→규정범위 경고, 공사기간 50년→개발기간 강제조정 경고, CAPEX 배터리 항목 -10억원→경고 등). 정상 기본값 상태에서는 신규 경고 11개 전부 숨김 상태이고 기존 화면 레이아웃에 변화가 없음을 확인, 이상치를 만들었다가 복원하는 전 과정에서 콘솔 오류·예외 0건.

**CAPEX 구성 확장 — 순수 공사비 외 부대비용 반영 (2026-09-11)**: "CAPEX에 순수 공사비 외에 금융수수료·보험료·건설이자·예비비 등을 반영해 달라"는 요청. 확인해 보니 이 4가지는 이미 총투자비 계산에 들어가 있었지만(예비비 %, F의 금융부대비용 %·건설기간 적용금리, CAPEX 항목 "건설보험·보증") D. CAPEX에는 13개 항목 합계 1,005억만 보여 실제 총사업비 1,130억과 달라 보였다. 계산 방식은 바꾸지 않고 구성을 드러내는 쪽으로 정리했다:
- **D. CAPEX (총사업비) = ① 공사비(EPC) + ② 개발·간접비 + ③ 부대비용**: ① 기자재·시공 7개, ② 인허가·설계·감리·민원·부지 5개, ③ 건설보험·보증 + **기타 부대비용(신규, 취득세·PM·법인설립 등, 기본 0)** 항목과 예비비·금융수수료(주선·약정 등)·건설기간 적용금리(건설이자)·DSRA 입력. 금융수수료·건설기간 금리·DSRA는 F. 금융·세무에서 D ③으로 옮겼다(입력 id 그대로 — 저장 시나리오·CSV·엑셀 호환).
- **총사업비 구성 표(실시간)**: ①②③과 ③의 세부(보험·기타·예비비·금융수수료·건설기간 이자·DSRA), 금액·비중, 합계 = 총투자비. 입찰단가와 무관하게 바로 계산되며 D 제목줄에 "총 1,130억" 표시. 요약 탭 산출 근거·엑셀 요약/입력값 시트도 같은 ①②③ 구성으로 바꿨다.
- **EPC 총액 직접 입력은 ① 공사비만 대체**(②·③ 항목은 항상 더함), 전환 시 ① 항목 합계(기본 960억)로 채운다. 기본값 결과는 그대로(22.51원/kWh). 예전에 총액 모드로 저장한 시나리오는 총액이 13개 전체 합계 의미였으므로 불러오면 ②·③만큼 총사업비가 늘어난다.
- **민감도 "EPC 총액 ±15%"는 ① 공사비만 변동**(라벨과 일치하도록). ②·③ 항목은 그대로, 금융수수료·건설이자·DSRA는 바뀐 조달액으로 재계산. 기준값은 불변(E-IRR 7.45%), 표 가장자리 값은 이전보다 작게 움직인다.
- **호환성**: CAPEX 항목 순서(= 시나리오 JSON 순서)는 그대로 두고 새 항목을 14번째로 추가 — 예전 13칸 JSON은 기타 부대비용 0으로 읽는다. 항목을 그룹별로 그리면서 화면 순서와 인덱스 순서가 달라져 저장·복원이 섞일 수 있어 인덱스 순서로 읽고 쓰도록 고쳤다.
- **검증**: 화면 점검 — 그룹 7/5/2칸, 구성 합계 = 총투자비 KPI, ①+②+③ = 총사업비, 기타 부대비용 20억 → 총투자비 1,152.5억·단가 22.74원(0으로 되돌리면 22.51), EPC 총액 모드 960억·단가 불변, 저장 순서(14칸, 보험 @11) 등 전부 통과. 엑셀 변환기 점검 20개 통과(구성 합계·총액 모드·예전 13칸 JSON 포함). 실제 화면에서 기타 부대비용 15억(총투자비 1,204.4억)·EPC 총액 1,000억(1,175.0억) 시나리오를 저장해 변환 → 총투자비·단가·IRR·NPV·점수·민감도 기준값 모두 화면과 일치, Excel(COM)로 복구 없이 열림 확인.

**용량 기본값 96MW 통일 — KCH 탭 설비용량을 계약용량에 연동 (2026-09-11)**: "기본 용량을 96MW로, 용량은 거의 바뀔 일이 없다"는 요청. 계약용량(입찰물량)은 이미 기본 96MW였고, 50MW로 달랐던 것은 KCH 개발수수료 탭의 설비용량(저장용량 200MWh)이었다 — 계약용량과 별개로 다시 입력해야 하는 독립 입력이었음.
- KCH 탭 **설비용량 = C. 발전매출의 계약용량, 저장용량 = 계약용량 × 6h**(공급량 산정 ① 방전가능용량과 같은 정의)로 연동하고 읽기 전용(계산값)으로 바꿨다 — 기본 96MW·576MWh, 용량을 바꿀 때는 계약용량 한 곳만 고치면 된다. 계약용량을 바꾸면 KCH까지 즉시 다시 계산.
